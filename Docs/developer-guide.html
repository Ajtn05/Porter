Porter

Developer guide for a native macOS Android file-transfer app over USB.

Porter uses ADB when USB debugging is ready and direct MTP when a phone is in File Transfer mode. The Swift package owns discovery, transfer semantics, and USB transports; the macOS app owns presentation and the read-only Finder bridge.

1. System shape

SwiftUI app (App/) | +-------------------+-------------------+ | | DeviceCoordinator TransferEngine discovery and selection queue, partials, resume, | verification, conflicts +--------------- DeviceTransport -------+ | +----------+----------+ | | ADBTransport MTPTransport USB debugging USB File Transfer

Kit/ contains the UI-independent model, discovery, transports, and engine. Every transport publishes TransportCapabilities, which the engine uses to choose safe resume, verification, and concurrency behavior.

2. USB transfers

TransportWhat it providesLimit to expose
ADBRanged reads, resumable writes, device-side SHA-256, modification dates, reliable sizes and capacity.Requires developer options and USB debugging.
MTPBrowse and copy without USB debugging.One stream, no dependable resume or device checksum; metadata and capacity are best effort.

Incoming bytes land in a .porterpart sidecar. ADB can resume and compare a device-side hash. MTP restarts interrupted copies and marks completed files unverified.

MTP transaction and listing behavior

The direct MTP stack includes protocol framing, an IOKit USB bulk pipe, a serial session, and path-to-handle resolution. A complete upload holds the pipe from SendObjectInfo through SendObject, so browsing cannot interrupt its data phase. Folder listings use one property-list request where supported and fall back to handle and object-info requests on other devices.

macOS ownership rule. ptpcamerad may claim the MTP interface first. Start Porter before plugging in the phone. If another process wins, unplug and reconnect. porterctl mtp and porterctl mtp-watch report the interface holder.

3. Discovery and Finder

USBDeviceMonitor distinguishes charge-only devices from phones publishing ADB or MTP. DeviceMerge combines USB and wired ADB listings into one row per phone.

The read-only File Provider extension sends metadata and whole-file requests through an App-Group bridge to the main app, which owns the USB transports. Signed Finder behavior still needs on-device validation.

4. Build and test

cd Kit
swift test

xcodegen generate
xcodebuild -project Porter.xcodeproj -scheme Porter -configuration Debug build

macOS 14+ and Xcode 26 are the project baseline. The app target needs a signing team in project.yml.
