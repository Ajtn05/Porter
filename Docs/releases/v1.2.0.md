# Porter v1.2.0

Porter v1.2.0 adds photo and video import, copy and paste between panes, and
safer transfer completion and folder navigation.

## Download and install

Requires macOS 14 or later. `Porter-1.2.0-macos-universal.zip` contains native
Apple silicon and Intel binaries. Unzip it and move `Porter.app` to Applications.
Start Porter before connecting the phone, then select File Transfer mode on
Android. USB debugging is optional; enabling it gives Porter the ADB transport.
Existing preferences are preserved.

**Distribution status:** this candidate is ad hoc signed and is not notarized.
macOS may block a downloaded copy. Developer ID signing and notarization remain
pending. The candidate is prepared for review and testing.

## Changes since v1.1.0

- Import Photos scans Camera (DCIM), Pictures, or the current phone folder on
  the selected storage. Choose photos and optional videos, a Mac destination,
  and Keep Both, Skip, or Replace. Review checks counts, filename collisions,
  source metadata, and space before queueing. Subfolders are preserved. Changes
  to the selection or options invalidate the review; scan and review can be
  cancelled.
- Command-C and Command-V copy between Mac and Android through the transfer
  queue. Finder file URLs can be pasted into the Android pane. Clipboard
  sources retain their original paths and phone after navigation or selection
  changes. Copy and Paste are also available in browser menus.
- Mac New Folder and Rename show errors inside the editable name dialog.
  Invalid names are rejected before file operations. Move to Trash processes
  the full selection, reports each failed item, and preserves remaining files
  for retry.
- Mac folder loading and history commit only after a successful read. Failed
  navigation and refresh preserve the last view and selection, with an inline
  Retry action for the failed destination.
- Transfer planning blocks different source files that would become one
  destination after sanitization, case folding, or flattening. Repeated source
  selections are deduplicated. File/folder conflicts block before copying.
- Each transfer owns a temporary file named with its persisted item ID.
  Separate queued copies cannot share partial bytes, including bulk downloads
  and copies from different phones. Copies to one final destination wait their
  turn.
- Conflict choices are checked again at completion. Unexpected destinations
  are preserved; Skip records a skipped copy; Replace if Newer checks fresh
  destination dates. Keep Both respects case-insensitive names and applies
  modification dates to the new copy.
- Mac replacements use an atomic rename. Phone replacements keep the original
  in a temporary backup until placement succeeds and attempt restoration if it
  fails. Failed recovery reports the retained backup path.
- ADB metadata lookups distinguish a missing file from permission errors,
  disconnects, and malformed replies. Concurrent conflict prompts queue, and
  dismissing a prompt resumes its planner with Skip. Copy settings and phone
  folder destinations are captured before asynchronous work.

Bundled Android platform-tools 37.0.1 ADB and upstream notices are included.
No separate ADB installation is required.

## Validation

All 211 PorterKit tests in 24 suites passed, including 17 transfer-safety tests
covering collision checks, per-item partials, late conflicts, Skip, Keep Both,
date checks, successful replacement, rollback, and failed recovery. ADB error
tests use a fixture executable, and transfer tests use fake phones.

The command-line browser validation passed 15 state checks and 36 app checks:
6 browser navigation, 4 browser recovery, 8 clipboard, 8 local file-operation,
7 photo import, and 3 conflict-prompt checks. Fixtures stay in the workspace;
Trash checks use simulated moves and clipboard checks use in-memory pasteboard
items. Validation did not launch Porter or contact a phone.

Release packaging checks the app, embedded extension, and bundled ADB for both
architectures, valid bundles, and local signatures. The package includes a
source archive and metadata identifying the same committed revision.

## Known limits and upgrade behavior

- Finder integration remains an experimental, read-only File Provider. Signed
  registration and real-device downloads need validation. Use Porter's browser
  for transfers.
- MTP transfers run one at a time, restart after interruption, and are marked
  unverified because MTP cannot compute a device-side checksum. Dates and
  storage-space reports are best effort.
- Phone replacement is not atomic across a disconnect or changes by another
  app. If recovery fails, use the backup path shown in the transfer error.
- Interrupted copies from older releases restart with the new temporary
  names. Older `.porterpart` files remain untouched; remove them only after
  confirming the related copy is complete.
- Photo import uses supported filename extensions and copies to a Mac folder.
  It does not add files to the Photos library or track previous imports.
- Desktop presentation, clipboard integration, photo import, and the new
  transfer behavior still need testing with real phones. Compatibility and
  sustained-load measurements remain limited.
- No phone-wide search, column/gallery views, writable Finder support, Wi-Fi
  transfers, watched folders, or APK sideloading.
